Your field guide

Set up your environment. Bring your problem-solving.

The challenge is beginner-friendly, but your laptop should be ready before you arrive. Read the setup notes, understand your team's responsibilities, and know what the judges will look for.

Before the event

Install a Linux virtual machine on your laptop and confirm that it is fully functional. You will use a Linux environment during the challenge, so make sure you can start the VM and work in it before event day.

  • Install a Linux VM and verify that it boots correctly.
  • Bring a laptop with enough battery or access to power.
  • Arrive ready to work in a team of four and take ownership of one service.

Event details

Location

Excel Lab, MITS Kochi

Time

2:00 PM – 6:00 PM

Team size

Four participants, each responsible for exactly one microservice.

How your team will be evaluated

Judges will look at how well the services work together and how clearly your team handles the challenges built into a distributed system.

Speed of the flow

Efficient, responsive network communication between microservices.

Error handling

Graceful failures, correct fallback loops, and useful HTTP error responses.

Presentation

A clear web client UI and an understandable real-time view of the network flow.

Security

Safe password hashing and proper session management across modules.

Bonus: monitoring

Live event-log dashboards for each microservice are highly recommended and earn bonus points.

Rules of the challenge

  1. Keep four separate services. The system must include acm-dns, acm-db, acm-server, and acm-app. Combining them into one monolith is not allowed.
  2. Discover services through DNS. Services must register with and discover one another through acm-dns. Direct service-to-service communication that bypasses DNS is prohibited.
  3. Never hardcode IP addresses. Supply every address dynamically at startup, through user input or environment variables. Even the DNS server address must be provided at runtime.
  4. Build an interactive web client. The acm-app must show a real-time visualization of network flows and background events.
  5. Use distributed ownership. Each of the four participants owns exactly one microservice. Work independently on each service until final integration. AI tools are permitted.
  6. Honor the OpenAPI contracts. Do not alter or remove any required endpoint or schema in the provided OpenAPI 3.0 YAML. You may add features and endpoints.
