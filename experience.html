A request that travels through your system

The event uses contract-driven development. Each service starts from a fill-in-the-blanks template and a strict OpenAPI 3.0 contract. Your implementation must honor those contracts so the separately developed pieces can communicate during integration.

1Configure DNSThe client receives a DNS server address at runtime.
2Resolve authDNS returns the current address for the auth service.
3Sign in or registerIf login fails, register the user and retry.
4Keep the sessionThe client extracts and persists the session cookie.
5Verify identityA request to /whoami confirms the active user.

Make network activity visible

The web client should not hide the work happening behind the screen. Show network hops and background events through a real-time visual indicator, such as icons that move through each stage of the flow.

Teams can earn bonus points by adding a live event-log dashboard for each microservice. That makes service registration, lookups, authentication, database calls, and failures easier to inspect during a demonstration.

Explore the fundamentals by doing

As you build, you will work with DNS, Linux, IP addresses, ports, TCP and UDP, web development, backend technologies, password hashing, and session management. The challenge is beginner-friendly: curiosity, problem-solving, teamwork, and adaptability are more important than arriving with every answer.
