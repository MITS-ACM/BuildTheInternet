BUILD_THE_INTERNET

A 4-hour hands-on technical challenge. Go beyond using the internet—build and connect your own mini internet system through contract-driven microservices.

LOC: EXCEL LAB, MITS KOCHI SYS_TIME: 14:00 - 18:00

SYSTEM_CONSTRAINTS

  • 01. STRICT MICROSERVICES Exactly 4 separate services must be built. Monolithic architectures will be rejected by the system.
  • 02. DYNAMIC DISCOVERY Direct inter-service communication is blocked. All services must resolve targets via the acm-dns registry.
  • 03. NO HARDCODED IPS Zero static IP addresses allowed. IPs must be injected at runtime via user input or environment variables.
  • 04. VISUAL TELEMETRY The acm-app client must be a web application featuring a real-time visual progress indicator of all backend network hops.
  • 05. ISOLATED DEVELOPMENT 1 Participant = 1 Microservice. AI tooling is permitted, but cross-module collaboration is restricted until the final integration phase.
  • 06. IMMUTABLE CONTRACTS Provided API endpoints and schemas cannot be modified or removed. Extending with new endpoints is permitted.

API_CONTRACTS

acm-dns

REGISTRY
GET/lookup?domain={name}
Resolves a domain name to its current destination IP address.
POST/register
Registers a domain name, mapping it to the incoming request's source IP.
{ "domain": "auth-service" }

acm-db

STORAGE
POST/db/users
Persists a new user record to storage.
{ "username": "...", "password_hash": "..." }
GET/db/users/{username}
Retrieves a stored user record for authentication checks.

acm-server

AUTH
POST/register
Hashes the password and creates a new user account.
{ "username": "...", "password": "..." }
POST/login
Validates credentials and issues a session_id cookie.
{ "username": "...", "password": "..." }
GET/whoami
Inspects the session cookie to return active user details.

acm-app

GATEWAY
Web client implementing the full flow visualization.
  • Accept DNS Server IP from user input.
  • Query DNS for the auth server address.
  • Attempt Login (If fail -> Register -> Retry Login).
  • Extract and persist the session_id cookie.
  • Verify Session via /whoami endpoint.
