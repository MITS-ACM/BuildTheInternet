Build The Internet 🌐

A 4-hour hands-on technical challenge. Build, connect, and troubleshoot your own mini internet system through contract-driven microservices.

Excel Lab, MITS Kochi 2:00 PM - 6:00 PM

⚠️ Important Rules

  • 1. True Microservices: Exactly 4 separate services. No monoliths.
  • 2. DNS Discovery Only: Services MUST use acm-dns to find each other. No direct communication without DNS resolution.
  • 3. Zero Hardcoded IPs: All IP addresses must be dynamic (e.g. inputted by user).
  • 4. Visual Client Web App: The Client must be a web app with a real-time visual progress indicator of backend events.
  • 5. Divide and Conquer: 1 Participant = 1 Microservice. AI tools allowed, but do not touch others' code until integration.
  • 6. Strict API Contracts: You cannot remove or change the provided endpoints. (You may add new ones).
  • ⭐ Bonus Points: Adding individual monitoring dashboards for each microservice.

Service API Contracts

📡 acm-dns

Dynamic Service Discovery

GET /lookup?domain={name}

Returns the destination IP for a registered domain.

POST /register

Registers a domain to the client's source IP.

Body: { "domain": "auth-service" }

💾 acm-db

Low-level User Storage

POST /db/users

Save a new user record.

Body: { "username": "alice", "password_hash": "..." }
GET /db/users/{username}

Fetch user record by username to retrieve password hash.

⚙️ acm-server

Auth & Session Management

POST /register

Creates a new user account.

Body: { "username": "alice", "password": "..." }
POST /login

Authenticates user and returns a `session_id` Cookie.

Body: { "username": "alice", "password": "..." }
GET /whoami

Inspects the session cookie to identify the current user.

🖥️ acm-app (Client)

Web Gateway & Visualizer

Expected Workflow:

  1. Take DNS Server IP as user input.
  2. Query DNS /lookup to find the server address.
  3. Attempt Login. If user doesn't exist, Register then Retry Login.
  4. Capture the session_id cookie from Login.
  5. Call /whoami to confirm the active session.
UI Requirement: Must feature a live, icon-based real-time display representing each of these steps as they occur!
